# Implement RegistryTransaction System Implementation Plan

## Overview
Create a robust, `IDisposable` registry transaction system to ensure atomic and safe registry manipulations. This will prevent inconsistent states by automatically rolling back changes if a process fails or isn't explicitly committed.

## Scope Definition (CRITICAL)
### In Scope
- Create `RegistryTransaction` class in `Tweaker/Utilities/RegistryTransaction.cs`.
- Implement `IDisposable` pattern for automatic rollback.
- Support `SetRegistryValue` and `DeleteRegistryValue` within the transaction.
- Track original state (KeyPath, ValueName, OriginalValue, OriginalKind) for precise restoration.
- Support explicit `Commit()` and `Rollback()`.

### Out of Scope (DO NOT TOUCH)
- Refactoring existing optimizations to use the new transaction system (this will be handled in future tickets).
- Modifying `RegistryBackupService` persistence logic.

## Current State Analysis
- **RegistryHelper.cs (line 209)**: `ExecuteRegistryTransaction` is a simple loop with no state tracking or rollback.
- **RegistryBackupService.cs (line 29)**: Has `RegistryBackupEntry` but is designed for global, persistent "Undo" rather than scoped transactions.
- **Direct Access**: Many classes (e.g., `UpdateChecker.cs:171`) perform direct, untracked registry writes.
