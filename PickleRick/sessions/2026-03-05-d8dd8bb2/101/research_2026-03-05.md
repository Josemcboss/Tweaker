# Research: Implement RegistryTransaction System

**Date**: 2026-03-05

## 1. Executive Summary
The current registry manipulation in the `Tweaker` project is performed using direct `Microsoft.Win32.Registry` calls in various optimization classes (e.g., `CpuOptimization.cs`, `BaseOptimization.cs`). While a `RegistryBackupService` exists, it is not consistently used (or used at all in detected code paths). A primitive `ExecuteRegistryTransaction` exists in `RegistryHelper.cs` but lacks true atomicity and rollback capabilities.

## 2. Technical Context
- **RegistryHelper.cs**: Contains static methods for `SetRegistryValue` (line 23), `GetRegistryValue` (line 83), and `DeleteRegistryValue` (line 184). It also has a `RegistryOperation` class (line 260) and an `ExecuteRegistryTransaction` method (line 209) that simply iterates through operations without state tracking.
- **RegistryBackupService.cs**: Provides a global, persistent backup mechanism using a JSON file. It defines `RegistryBackupEntry` (line 29) which tracks `KeyPath`, `ValueName`, `OriginalValue`, and `ValueKind`. Key methods include `BackupValue` (line 88) and `RestoreAll` (line 228).
- **BaseOptimization.cs**: Provides wrapper methods (`SetRegistryDWord` at line 61, `SetRegistryString` at line 72) that delegate to `RegistryHelper`.
- **Optimizations (e.g., CpuOptimization.cs)**: Many optimizations still use raw `RegistryKey.OpenSubKey` and `key.SetValue` calls, bypassing the helpers and any backup logic (e.g., `UpdateChecker.cs:171`).

## 3. Findings & Analysis
- **Lack of Atomicity**: If a sequence of registry changes fails midway, the system is left in an inconsistent state (see `RegistryHelper.cs:209`).
- **No Automatic Rollback**: Current "transactions" in `RegistryHelper.cs:209` do not store original values, making it impossible to undo changes if one fails or if the session is interrupted.
- **Manual Restore**: Restoration currently depends on the user manually triggering a revert via `RegistryBackupService.RestoreAll` (line 228), which then applies hardcoded "default" values (e.g., `CpuOptimization.DisableSystemResponsivenessOptimization` sets `SystemResponsiveness` to 20, even if the user's original value was different).
- **Inconsistent Backup**: `RegistryBackupService` is initialized but not utilized by the core registry manipulation methods in `RegistryHelper.cs` (lines 23-81).

## 4. Technical Constraints
- **Permissions**: Registry operations require administrative privileges (`runas` verb or manifested as `requireAdministrator`).
- **Registry Value Kinds**: Must handle `DWord`, `String`, `QWord`, `Binary`, etc., correctly during backup and restore.
- **Hive Mapping**: Needs to support `HKEY_LOCAL_MACHINE`, `HKEY_CURRENT_USER`, etc., consistently.

## 5. Architecture Documentation
- **Current Pattern**: Static helper classes (`RegistryHelper`) and abstract base classes (`BaseOptimization`) providing wrapper methods.
- **New Pattern Goal**: An `IDisposable` transaction scope that captures state automatically and requires an explicit `Commit()` to prevent rollback on disposal.
