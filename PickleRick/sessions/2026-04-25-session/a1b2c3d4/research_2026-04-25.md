# Research: Core Hardware Infrastructure

**Date**: 2026-04-25

## 1. Executive Summary
The current hardware detection system is implemented in `Tweaker\Utilities\HardwareDetector.cs`. It uses synchronous WMI queries which can block the UI thread if not called carefully. The data model is limited and lacks detailed specifications like CPU clock speeds, RAM sticks configuration, or GPU VRAM. The task is to refactor this into an asynchronous service-based architecture with a more comprehensive data model.

## 2. Technical Context
- **Existing Implementation**: `Tweaker\Utilities\HardwareDetector.cs` (static class).
- **Data Model**: `HardwareInfo` is currently defined inside `HardwareDetector.cs`.
- **Affected Components**:
    - `Tweaker\ViewModels\MainWindowViewModel.cs`: Calls `HardwareDetector.Detect()` in constructor.
    - `Tweaker\App.xaml.cs`: Calls `HardwareDetector.Detect()` in a fire-and-forget `Task.Run`.
- **Current Behavior**: Synchronous WMI queries using `ManagementObjectSearcher`. It detects basic names and counts for CPU, GPU, RAM, and Storage.

## 3. Findings & Analysis
- `HardwareDetector.cs` (L26-L165) contains detection logic for GPU, CPU, Storage, and RAM.
- `HardwareInfo` (L10-L24) contains basic properties: `GPUName`, `IsNvidia`, `IsAMD`, `IsSSD`, `TotalRAMGB`, `CPUCores`, `WindowsVersion`, `IsWindows11`, `CPUName`, `IsRyzen`, `IsIntel`, and `DetectedAntiCheats`.
- `MainWindowViewModel.cs` (L245) assigns the result of `HardwareDetector.Detect()` to a `HardwareInfo` property.
- `App.xaml.cs` (L45) pre-warms the detection in a background thread.
- `AntiCheatDetector` (L167-L215) is also in `HardwareDetector.cs`, which violates SRP. This should likely be moved to its own service later, but for now, we focus on the hardware infrastructure.

## 4. Technical Constraints
- Must use `System.Management` (WMI) as per requirements.
- Must be asynchronous (`ScanAsync()`).
- Must be a Singleton service.
- New fields required:
    - CPU: Vendor, Cores, Threads, Clock.
    - GPU: Vendor, VRAM.
    - RAM: Total, Sticks.
    - Storage: Type, Capacity.
    - OS: Build.

## 5. Architecture Documentation
- Current project uses a mix of static utilities and DI-ready services (in `Tweaker\Services`).
- ViewModels use `RelayCommand` and `AsyncRelayCommand` (from `CommunityToolkit.Mvvm` or similar, based on `MainWindowViewModel.cs` grep).
- The project is a WPF application using .NET (based on `.csproj` names and `App.xaml`).
